# Docker Deployment Guide

This guide explains how to deploy the LLMScope platform using Docker on your local machine.

## Prerequisites

- Docker Desktop (or Docker Engine) installed and running
- Docker Compose v2.0 or higher
- Git (to clone the repository)
- At least 4GB of available RAM

## Quick Start

### 1. Clone the Repository

```bash
git clone <your-repository-url>
cd LLMScope
```

### 2. Configure Environment Variables

Copy the example environment file and configure it with your settings:

```bash
cp .env.example .env
```

The `.env` file has been pre-configured with a secure secret key. You can modify these settings if needed:

```bash
# Security (already generated)
SECRET_KEY=<auto-generated-key>

# Authentication
API_KEY=llmscope-local-key

# Single-tenant mode (recommended for self-hosted)
SINGLE_TENANT_MODE=true
REQUIRE_AUTH=true
```

Optional configurations (defaults are already set):
- `RATE_LIMIT_REQUESTS`: Max requests per period (default: 1000)
- `RATE_LIMIT_PERIOD`: Rate limit period in seconds (default: 60)
- `CORS_ORIGINS`: Allowed CORS origins
- `ENABLE_WORKERS`: Enable background workers (default: true)
- `WORKER_CONCURRENCY`: Number of worker threads (default: 4)

### 3. Build and Start Services

```bash
# Build and start all services in detached mode
docker-compose up -d

# Or build with no cache (if you need a fresh build)
docker-compose up -d --build
```

This will start:
- **PostgreSQL** database on port `5434` (host) / `5432` (container)
- **Redis** cache on port `6380` (host) / `6379` (container)
- **Backend API** on port `8000`
- **Frontend** React app on port `3000`

### 4. Access the Application

Once all services are running, open your browser and navigate to:

```
http://localhost:3000
```

The frontend will automatically proxy API requests to the backend.

### 5. Verify Services

Check that all services are running:

```bash
# View running containers
docker-compose ps

# View logs from all services
docker-compose logs

# View logs from a specific service
docker-compose logs frontend
docker-compose logs backend
docker-compose logs postgres
docker-compose logs redis
```

Health check endpoints:
- Frontend: [http://localhost:3000](http://localhost:3000)
- Backend API: [http://localhost:8000/health](http://localhost:8000/health)
- Backend API Docs: [http://localhost:8000/docs](http://localhost:8000/docs)

## Management Commands

### Stop Services

```bash
# Stop all services
docker-compose down

# Stop and remove volumes (deletes all data)
docker-compose down -v
```

### Restart Services

```bash
# Restart all services
docker-compose restart

# Restart a specific service
docker-compose restart backend
```

### View Logs

```bash
# Follow logs from all services
docker-compose logs -f

# Follow logs from a specific service
docker-compose logs -f backend

# View last 100 lines
docker-compose logs --tail=100
```

### Rebuild Services

```bash
# Rebuild all services
docker-compose build

# Rebuild a specific service
docker-compose build frontend

# Rebuild with no cache
docker-compose build --no-cache
```

### Access Container Shell

```bash
# Access backend container
docker-compose exec backend /bin/bash

# Access database
docker-compose exec postgres psql -U postgres -d llmscope
```

## Architecture

The Docker setup consists of four main services:

### 1. Frontend (React + Nginx)
- **Port**: 3000
- **Location**: `frontend/` directory
- **Technology**: React, Vite, TailwindCSS
- **Container**: Multi-stage build with Node.js (build) and Nginx (serve)
- **Features**:
  - Production-optimized build
  - Gzip compression enabled
  - API proxy to backend
  - React Router support

### 2. Backend (FastAPI)
- **Port**: 8000
- **Location**: `backend/` directory
- **Technology**: Python 3.11, FastAPI, SQLAlchemy
- **Features**:
  - RESTful API for event ingestion
  - Real-time WebSocket streaming
  - Database migrations via Alembic
  - Rate limiting and authentication
  - Background workers for processing

### 3. PostgreSQL
- **Port**: 5434 (host) → 5432 (container)
- **Version**: PostgreSQL 15
- **Data**: Persisted in Docker volume `postgres_data`

### 4. Redis
- **Port**: 6380 (host) → 6379 (container)
- **Version**: Redis 7
- **Usage**: Caching, queue management, and event processing
- **Data**: Persisted in Docker volume `redis_data`

## Project Structure

```
LLMScope/
├── frontend/                 # React frontend application (for Docker)
│   ├── src/
│   ├── package.json
│   └── vite.config.ts
├── backend/                  # Main LLMScope backend platform (for Docker)
│   ├── app/
│   ├── requirements.txt
│   └── alembic.ini
├── playground/               # Separate deployment (online, without Docker)
│   ├── frontend/            # Playground frontend
│   └── backend/             # Playground backend
├── Dockerfile.frontend       # Frontend Docker build
├── Dockerfile.backend        # Backend Docker build
├── docker-compose.yml        # Orchestration configuration
├── nginx.conf               # Nginx configuration
├── .env                     # Your environment variables
├── .env.example             # Environment template
└── .dockerignore            # Docker build exclusions
```

**Note**:
- Docker deployment uses `frontend/` and `backend/` from the root directory
- The `playground/` folder is for separate online deployment (without Docker)
- Both setups are independent and can run simultaneously

## Network Architecture

All services communicate on a private Docker network (`llmscope-network`):

```
User → Frontend (nginx:80) → Backend (uvicorn:8000)
                                  ↓
                          PostgreSQL (5432)
                                  ↓
                              Redis (6379)
                                  ↓
                         Background Workers
```

## Data Persistence

Docker volumes are used to persist data:
- `postgres_data`: Database files
- `redis_data`: Redis cache

To backup data:
```bash
# Backup PostgreSQL
docker-compose exec postgres pg_dump -U postgres llmscope > backup.sql

# Restore PostgreSQL
docker-compose exec -T postgres psql -U postgres llmscope < backup.sql
```

## Troubleshooting

### Port Already in Use

If you get port conflict errors, you can change the ports in `docker-compose.yml`:

```yaml
services:
  frontend:
    ports:
      - "3001:80"  # Changed from 3000
  backend:
    ports:
      - "8002:8001"  # Changed from 8001
```

### Database Connection Issues

Check if PostgreSQL is ready:
```bash
docker-compose logs postgres
```

Wait for the message: `database system is ready to accept connections`

### Frontend Not Loading

1. Check if the build completed successfully:
```bash
docker-compose logs frontend
```

2. Verify nginx configuration:
```bash
docker-compose exec frontend cat /etc/nginx/conf.d/default.conf
```

### Backend API Errors

1. Check environment variables:
```bash
docker-compose exec backend env | grep PLAYGROUND
```

2. Verify database connection:
```bash
docker-compose exec backend python -c "from app.database import engine; engine.connect()"
```

### Reset Everything

If you need to start fresh:
```bash
# Stop and remove all containers, networks, and volumes
docker-compose down -v

# Remove all images
docker-compose down --rmi all

# Start fresh
docker-compose up -d --build
```

## Environment Variables Reference

### Required Variables

| Variable | Description | Example |
|----------|-------------|---------|
| `SECRET_KEY` | Secret key for session encryption | Generated via `openssl rand -hex 32` |
| `API_KEY` | API key for authentication | `llmscope-local-key` |

### Optional Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `DATABASE_URL` | `postgresql://postgres:postgres@postgres:5432/llmscope` | Database connection URL |
| `REDIS_URL` | `redis://redis:6379` | Redis connection URL |
| `SINGLE_TENANT_MODE` | `true` | Enable single-tenant mode |
| `REQUIRE_AUTH` | `true` | Require API key authentication |
| `CORS_ORIGINS` | `http://localhost:3000,http://localhost:8000` | Allowed CORS origins |
| `RATE_LIMIT_REQUESTS` | `1000` | Max requests per period |
| `RATE_LIMIT_PERIOD` | `60` | Rate limit period in seconds |
| `ENABLE_WORKERS` | `true` | Enable background workers |
| `WORKER_CONCURRENCY` | `4` | Number of worker threads |

## Security Considerations

1. **Never commit your `.env` file** - It contains sensitive information
2. **Generate a strong secret key** - Use `openssl rand -hex 32`
3. **Protect your API keys** - Never expose them in client-side code
4. **Use HTTPS in production** - The current setup is for local development only
5. **Update CORS origins** - Restrict to trusted domains in production

## Production Deployment

This Docker setup is optimized for local development. For production:

1. Use managed database services (AWS RDS, Google Cloud SQL)
2. Use managed Redis (AWS ElastiCache, Redis Cloud)
3. Enable HTTPS with SSL/TLS certificates
4. Use secrets management (AWS Secrets Manager, HashiCorp Vault)
5. Implement proper logging and monitoring
6. Use container orchestration (Kubernetes, ECS)
7. Set up CI/CD pipelines
8. Implement database backups
9. Configure resource limits and health checks
10. Use CDN for static assets
